# 1 概要

## 1.1 目的

利用者が、漠然とした希望しか持っていない場面で、**いくつかの質問に答えるだけで、適した候補と、その理由を得られる**ようにします。
最初のテーマは旅行先です。「海がきれい・1 週間・島でのんびり」といった曖昧な希望から、候補を絞り込みます。

## 1.2 経緯

| 時期 | 内容 |
|---|---|
| 2000 年ごろ | 発案 |
| 2002 年 | Java アプレット（画面）、CGI、PostgreSQL（データ）で試作。候補が持つ点数と、回答に付けた点数を掛け合わせて合計し、順位を決める方式。**実用には至らず** |
| 2002 年版の課題 | データの準備が難しい／固定の評価では多様な希望に対応しにくい／「日程 5 日・予算 15 万円まで」のような絶対条件を扱えない／品質が低い |
| 20 年後 | LLM の発展により、当時考えていたことを現在の技術で実現できると考え、作り直した |
| 現在 | Vue.js ＋ Flask ＋ 複数の LLM。GCP 上で稼働 |

詳しい比較は [8 章](08-2002-vs-now.md)にまとめています。

## 1.3 実装状況

| 領域 | 状態 | 備考 |
|---|---|---|
| 対話の流れ（質問 → 回答 → 提案） | 実装済み | 固定の質問と、AI が作る質問の両方 |
| テーマ指定の汎用画面 | 実装済み | テーマ、質問の作成指示、提案の作成指示、回答者へのアドバイスを入力 |
| 複数の提供元の切り替え | 実装済み | OpenAI、Gemini、Groq |
| 自動テスト（偽の AI） | 実装済み | 40 件超。ネット接続と課金なしで、数秒で終わる |
| 回帰テスト（実際の AI） | 実装済み | 複数のテーマと提供元で、成功率と失敗の内訳を集計 |
| 自前 AI の接続口 | 枠のみ | 現状はダミー応答を返す |
| 旅行先データ・RAG | 開発中 | **現行版には入っていない** |
| 決定的なスコア計算 | 計画中 | 現行版では、点数も AI が出している。方式は[参考実装](../reference/qar_ref/scoring.py)で検証 |
| ログ・評価の基盤 | 一部 | 回帰テストの集計と、アプリのログのみ |

## 1.4 現状の課題

**既存の Web 検索や、一般的な AI の利用と、十分に差別化できていません。**
AI が答えを作るだけでは、利用者が AI に直接尋ねた場合と変わりません。
そこで、[9 章](09-roadmap.md)のとおり、**根拠のあるデータと、決定的なスコア計算を持ち、AI はその前後（入力の解釈と、説明の生成）に限る**方向を考えています。
