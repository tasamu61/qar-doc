# 7 セキュリティ方針

具体的な実装や設定値は、運用上の理由で公開していません。ここでは、**設計の原則**を示します。

## 7.1 原則

| 原則 | 内容 |
|---|---|
| 入口で検証する | 利用者から受け取る値は、信用しない。使える値を**許可リストで限定**し、形式を検証する |
| 動的な解決をしない | 利用者の入力で、呼び出すモジュールやファイルを決めない |
| 利用を制限する | 外部 API の費用や、サービスの安定に影響するため、利用回数に制限をかける |
| 秘密情報を持ち込まない | API キーなどは、コードやリポジトリに含めない。環境変数で渡す |
| AI の出力も信用しない | 返事の形式と、表示してよい内容（例：リンクのスキーム）を検証してから使う |
| 公開範囲を最小にする | 本番のソースは非公開。公開するのは、設計の資料と、書き下ろしの参考実装 |
| 直したら、テストで固定する | 見つけた不備は、修正と同時に、再発を防ぐテストを加える |

## 7.2 自己レビュー

定期的に、自分のコードを**攻撃者の視点**で見直しています。
入力の経路、ファイルの配信、外部への呼び出し、設定の初期値、といった観点です。
見つけた不備は、修正し、テストで固定します（[5.5](05-quality.md)）。

## 7.3 参考実装での表現

- 許可リスト：[`providers.py`](../reference/qar_ref/providers.py)（登録外の名前を拒否）
- 出力の検証：[`schema.py`](../reference/qar_ref/schema.py)（`javascript:` などのリンクを拒否）
