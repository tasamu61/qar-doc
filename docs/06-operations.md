# 6 運用

## 6.1 実施していること

| 項目 | 内容 |
|---|---|
| 稼働環境 | GCP 上で稼働 |
| 秘密情報 | 各 AI の API キーは、**環境変数で渡し、ソースコードに含めない** |
| ログ | アプリケーションがリクエストの処理状況を記録する。回帰テストの集計も記録として使う |
| 変更前の確認 | 偽の AI による自動テストを実行してから反映する（[5 章](05-quality.md)） |
| AI 側の変化の検知 | 実際の AI による回帰テストを、回数と頻度を決めて実行する |
| 公開範囲 | ソースコードは非公開。資料と参考実装のみを公開 |

## 6.2 運用の考え方

- **外部 API に依存するため、止まる・変わる前提で作る。** 提供元を切り替えられる構成にしておき、1 社の不調が全体の停止にならないようにする。
- **費用は、仕組みで抑える。** 実際の AI を呼ぶテストは回数を決めて実行し、日常の確認は偽の AI で行う。
- **変更は、小さく、戻せる形で行う。** 変更の理由と、挙動が変わる点を記録する。

## 6.3 今後の強化

- 利用状況と費用の見える化（提供元ごとの呼び出し回数、失敗率の推移）
- 回帰テストの定期実行と、成功率の推移の記録
- 提供元の障害時の、自動的な切り替え
