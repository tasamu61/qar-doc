# 8 2002 年版との比較

2002 年版の資料は、[`archive/2002/`](../archive/2002/index.html) に、原文のまま残しています。

## 8.1 比較表

| 観点 | 2002 年版 | 現行版 |
|---|---|---|
| 画面 | Java アプレット | Vue.js |
| サーバー | CGI（Apache） | Flask |
| データ | PostgreSQL（候補・質問・回答・点数） | 候補は AI が生成。固定の質問はプログラムに保持（データベースは持たない） |
| 質問 | 人が設計して、データとして登録 | 固定の質問、または AI が作る質問 |
| 評価 | **積和スコア**（回答の点数 × 候補の点数の合計） | AI が、候補とスコアを出す |
| 再現性 | **高い**（同じ入力なら同じ結果） | 低い（AI の揺れがある） |
| 説明可能性 | **高い**（点数の内訳を示せる） | AI の文章による説明 |
| 準備するもの | 着眼点、候補の点数、回答の点数（**データの準備が重い**） | プロンプト（準備は軽い） |
| 絶対条件の扱い | 苦手（日程・予算の上限を越える候補が上位に来る） | AI の解釈しだい |
| 運用上の課題 | データ不足、品質 | **AI の仕様変更**、差別化 |

## 8.2 2002 年版の方式

2002 年版は、次の式で、候補の適合度を出します。

```
適合度（候補） ＝ Σ （回答が持つ点数［着眼点 k］ × 候補が持つ点数［着眼点 k］）
```

たとえば、着眼点が「日程が短い」「海がきれい」「現地物価が安い」の 3 つで、
利用者が「日程」を 2、「海」を 3 の重みで重視したとき、沖縄は `12×2 + 12×3 = 60` になります
（候補の点数は 2002 年版の資料の例、重みは説明のための仮定）。
計算の内訳が見えるので、**なぜその順位かを、数字で説明できます。**

## 8.3 20 年で変わったこと

- **データ準備の壁が下がった。** 質問も、候補も、説明も、AI が作れる。
- **入力が自由になった。** 選択式だけでなく、自由な文章で希望を伝えられる。
- **一方で、決定性と説明可能性を失った。** 同じ入力でも結果が揺れ、順位の根拠が曖昧になった。
- **運用の課題が変わった。** データ不足から、外部 AI の仕様変更への追従へ。

## 8.4 20 年経っても残っていること

- **質問に答えて、提案を受ける**、という構造
- **着眼点（評価の軸）**で考える、という発想
- 利用者が納得できる**根拠**を示したい、という要求
- 2002 年版の課題の一部（絶対条件の扱い）は、現在でも、決定的な処理のほうが得意

この比較から、**2002 年版の長所（決定性・説明可能性）と、現在の AI の長所（自由な入力・説明文の生成）を組み合わせる**方針が出てきます（[9 章](09-roadmap.md)）。
